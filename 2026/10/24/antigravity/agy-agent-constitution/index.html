Agy CLI 專案管理（Agent Project Governance） 是指透過 Google 新一代 Antigravity CLI (agy) 命令列工具，並於專案根目錄建立 AGENT.md 最高憲法，以嚴格規範 AI 代理人的角色權責、架構邊界與交付標準的工程體系。其實踐流程分為三步：第一步於本機終端機安裝與初始化環境；第二步擬定剛性負面邊界與型別規範；第三步指揮 Agent 在受約束的軌道上自動生成程式碼與單元測試。

在上一篇文章中，我們確立了「Prompt 是餵飼料，Workflow 才是養殖場」的核心觀念。

後來我真的帶著好奇心跑去研究與觀察了現代化智慧養豬場，結果發現一個極具衝擊力的真相：

在現代養殖業裡，真正累人的早就不是「餵豬」本身（小豬自己會吃、會睡、會長大），最折磨場長的其實是「管理」！

你必須隨時管理環境溫濕度、人員進出的生物安全隔離規範、精準調配飼料配方、定期記錄各項生理數據，還有防止外部病毒入侵的層層標準作業程序（SOP）。

回到軟體開發，情況竟然一模一樣。基礎語法的撰寫已經被 AI 大幅簡化，真正讓資深工程師瀕臨爆肝的反而是管理——管理 Codebase 邊界、管理 Context 雜訊、管理 AI Agent 的行為準則，以及防止未經驗證的套件入侵現有架構。

為了拯救被管理壓垮的工程師，今天我們要正式請出 Google 的命令列神器：Agy CLI，並在專案中建立這座智慧養殖場的最高管理憲法——AGENT.md！

智慧養豬場 vs 軟體工程：概念對照大表

在讓工具進駐專案前，我們先把「智慧養豬場」與「AI 驅動軟體工程」的對照關係梳理清楚。搞懂這張映射表，你就能一眼看穿自動化架構的管理本質：

智慧養豬場元件軟體工程 (Software Engineering)現代 AI 工作流對應核心管理職責
養豬場 (Farm)專案儲存庫 (Repository)Git Codebase / 專案架構劃分獨立模組與元件生物安全（Shadow DOM）隔離區
豬隻 (Pigs)AI 代理人 (AI Agent)Agy CLI / Task Agent執行具體的程式碼生成、重構與測試任務
飼料 (Feed)上下文 (Context)Prompts / Data Contracts / Snippets提供高密度、剪枝後的乾淨輸入，避免 Context Rot
飼養守則 (Breeding Rules)指令規範 (Instructions)AGENT.md / System Instruction約束 AI 的行為規範、命名原則與輸出格式
場長 (Pig Farmer)架構師 / 工程師 (Engineer)Workflow & Process Architect不再手動敲擊每行程式碼，轉為設計產線與驗證閉環

第二步：建立專案最高管理憲法 AGENT.md

養豬場如果沒有公佈「場內管理守則」，飼育員跟豬隻就會亂成一團；專案如果沒有 AGENT.md，Agy CLI 進來就會像野豬闖進菜園一樣隨便亂寫！

AGENT.md 是放置於專案根目錄（或 .agents/ 目錄）下的 Markdown 檔案。Agy CLI 在每次啟動或執行任務時，都會優先讀取這份檔案作為最高 System Instruction。

📄 實戰範例：專案根目錄下的 AGENT.md

這份文件的靈魂在於：正面界定職責，負面畫出紅線。 只要寫清楚「嚴禁引入肥大 Runtime」與「樣式必須完全隔離」，AI 就不會偷偷幫你安裝無關套件。

第三步：指揮 Agy CLI 遵循憲法生成元件

當 AGENT.md 建立完成後，你的專案就具備了剛性防護網。現在你可以放心地讓 Agy CLI 讀取專案環境並進行開發：

sequenceDiagram
    autonumber
    actor Boss as 場長 (工程師)
    participant Agy as Agy CLI
    participant Const as AGENT.md 專案憲法
    participant Codebase as 專案程式庫

    Boss->>Agy: 下達建立 pig-health-card 元件需求
    Agy->>Const: 讀取角色規範與 Shadow DOM 隔離邊界
    Agy->>Codebase: 檢視現有目錄結構
    Agy-->>Boss: 產出高隔離度元件原始碼與 pig-health-card.test.ts

因為受到 AGENT.md 的約束，Agy CLI 產出的程式碼將會自動遵守 Shadow DOM 隔離、零全域樣式污染，並主動附帶單元測試檔——這就是自動化工程管理的第一步！

結語：從勞動工人升級為產線管理者

當你把 AGENT.md 設定好的那一刻，你就完成了一次關鍵的角色轉變：

你不再是蹲在專案裡一行行手搓語法的苦力工人，而是立下了管理規則、指揮 Agy CLI 在特定軌道上運行的產線管理者。

常見問題 FAQ

Q1：AGENT.md 應該放在專案根目錄還是子目錄？

Agy CLI 與 Antigravity 生態系支援專案根目錄的 AGENT.md，亦相容 .agents/AGENTS.md。建議將專案全域憲法放置於根目錄，模組專屬規範則可配合 Rules 機制配置於子目錄。

Q2：如果在對話中 AI 違反了 AGENT.md 的規則該怎麼辦？

首先檢查規則是否過於冗長或語意模糊。將核心禁令改為明確的條列清單，並使用強烈關鍵詞（如「嚴禁使用」、「必須提供」）。必要時可透過後續章節說明的 Rules 與 Hooks 建立自動化卡關驗證。

Q3：團隊多人協作時如何維護這份憲法？

將 AGENT.md 納入 Git 版本控制，將其視同專案的架構設計文件（ADR）。團隊成員提出架構調整時，必須透過 Pull Request 共同審查這份文件的修訂。
